\section*{Overview}

AI Stock Predictor is an experimental AI platform designed to:

\begin{itemize}[leftmargin=1.5em]
\item Run multiple AI models simultaneously
\item Produce N outputs per model (outputs 1..N)
\item Restrict outputs to discrete values between 0.00 and 0.35
\item Map outputs directly to operational trading actions
\item Ingest full webpages as binary inputs plus structured market data
\item Continuously generate alternative models via randomized mutation
\item Automatically promote better-performing models
\item Track portfolio profitability as the primary evaluation metric
\item Provide a monitoring dashboard for observability
\end{itemize}

Full system design details are documented in \texttt{ARCHITECTURE.md}.

% ------------------------------------------------
\section*{Core Concepts}

\subsection*{Discrete Action Output Contract}

Each model produces:

\begin{verbatim}
scores: List[float]
\end{verbatim}

Outputs must normalize to the following discrete action values:

\begin{center}
\begin{tabular}{ll}
\toprule
Score & Action \
\midrule
0.35 & Invest \
0.30 & Divest \
0.25 & Buy shares \
0.20 & Sell shares \
0.15 & Convert currency \
0.10 & Explore new/random site \
0.05 & Analyze similar site \
0.00 & Wait / No action \
\bottomrule
\end{tabular}
\end{center}

A normalization layer enforces this contract before any operational decision.

% ------------------------------------------------
\subsection*{Multi-Model Runtime}

The runtime system executes:

\begin{itemize}
\item One baseline model
\item N continuously evolving alternative models
\end{itemize}

Models are evaluated independently using profitability, stability, and loss-reduction metrics.

% ------------------------------------------------
\subsection*{Continuous Model Evolution}

Model variants may be created via:

\begin{itemize}
\item Architecture changes
\item Parameter mutation
\item Feature pipeline adjustments
\item Training window variation
\end{itemize}

Better-performing models are automatically promoted, with full audit logging.

% ------------------------------------------------
\subsection*{Data Inputs}

Supported inputs include:

\begin{itemize}
\item Raw binary webpage ingestion
\item Market price feeds
\item Financial APIs
\item News and sentiment data
\item Economic indicators
\end{itemize}

All inputs normalize into a shared feature representation.

% ------------------------------------------------
\subsection*{Portfolio Evaluation}

Current simplified rule:

\begin{quote}
A model is considered better if it produces more profit or consistently smaller losses.
\end{quote}

Advanced trading risk controls remain future work.

% ------------------------------------------------
\subsection*{Feedback and Logging}

Each prediction cycle records:

\begin{itemize}
\item Model version
\item Inputs used
\item Raw and normalized outputs
\item Interpreted actions
\item Portfolio state snapshot
\item Resulting profit or loss
\end{itemize}

This data supports retraining and long-term evaluation.

% ------------------------------------------------
\subsection*{Monitoring Dashboard}

Minimum dashboard capabilities:

\begin{itemize}
\item Prediction outputs per model
\item Portfolio performance visualization
\item Model comparison metrics
\item Promotion history
\item Historical prediction charts
\item Webpage ingestion visibility
\end{itemize}
